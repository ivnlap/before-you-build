# Contributing

Thanks for helping make Before You Build more useful.

## Good contributions

- **New tests** for the [catalog](skills/byb-test-plan/references/test-catalog.md): what it tests, the evidence level it can reach, cost, steps, pitfalls.
- **Worked examples** from real projects (anonymise people and numbers you can't share; say what's real and what's changed).
- **Behaviour checks** for [evals/](evals/), especially cases where a skill flattered you or moved a bar.
- **Translations** of the method and skills.
- **Fixes** to wording that is unclear for people who are not product managers.

## Rules of the house

1. Keep it small. A change that adds a new skill needs a strong reason; improving an existing one is usually better.
2. Plain language. If a term needs a book to explain, explain it in a line or drop it.
3. Write original text. Cite the ideas you build on in [method/sources.md](method/sources.md); don't paste copyrighted text.
4. Every skill keeps the shared ground rules (claim status, evidence ladder, no "validated", counts with denominators).
5. Run the relevant behaviour checks before opening a pull request and say which ones you ran.

## Stories

Used the kit on a real idea? Open an issue with the `story` label: what the idea was, which verdicts you reached, and what you'd change in the kit.
